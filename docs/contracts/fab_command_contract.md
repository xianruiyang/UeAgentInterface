# Fab command contract

Fab commands run in the Editor against its installed Fab plugin. My Library, status and download authorization use existing native sign-in. Native taxonomy and free-catalog search/detail use public same-origin requests without requiring a native login first. The SDK never receives access/refresh tokens, browser cookies, signed download URLs or private library/listing identities. A background native browser performs catalog requests; HTTP and BuildPatchServices transfer downloads into project-local `Saved/UAI/Fab` storage.

| Command | Contract |
| --- | --- |
| `fab.status` | Verify plugin, native-session availability to UAI and actual My Library access from its background browser. It does not read the native Fab tab's signed-in UI. |
| `fab.open` | Explicitly open Fab's native tab for persistent login or user interaction; never called implicitly by queries. Opening is not authentication proof. |
| `fab.categories` | Read native product types/category tree; default depth 1, depth 0 explicitly requests a complete subtree. Stable native slugs/codes are reusable search filters. |
| `fab.search` | Default owned library; optional free catalog. Native keywords/type/category filters, free-catalog `styles` facets, public listing links and explicit page/has_more/next_page. |
| `fab.asset` | Resolve exact name plus shared semantic selection, optionally a free-catalog public `listing_url`, then return bounded description, public listing link, reported licenses and actual format/file/version choices. |
| `fab.download` | Select one actual downloadable file; obtain fresh authorization, transfer, verify, publish a readable local completion record. No purchase, claiming or EULA acceptance. |
| `fab.downloads` | Offline local completion-record listing, 20 per page. It does not rehash every cached file. |
| `fab.files` | Offline file inventory, including every ZIP entry; substring query and 20-entry pagination, without extraction. |
| `fab.import_asset` | Fresh cache verification, native content publication or AssetTools import, shared persistence/rollback and independent package reload. |

All nine use the shared [Operation lifecycle](long_running_session_public_commands.md). The SDK consumes the completed command through `finish_result()`. A successful initial submission is not a successful catalog request, download or import. Local timeouts retain custody; recovery resumes the original operation without replay. Queued cancellation is consumed before any cache hit or local fast path and does not wait for an unrelated active transfer. Cancellation is complete only after the owned native task has stopped. Download cancellation never publishes an incomplete cache as ready. Editor exit cancels and drains its owned transfers and verification work before releasing completion callbacks. Native importer calls may be synchronous: cancellation is observed at the next controlled boundary, not by forcibly interrupting UE code.

`fab.downloads` and `fab.files` read the currently published local completion records on the game thread without joining the serial catalog/download/import queue. An active network request, transfer or background verification therefore does not delay these reads until that operation finishes. Receipt withdrawal/publication shares this thread; payload writers run only while no valid completion record is published. Reads do not alter the active job or its cancellation and authentication state. They still use the shared Operation and honor cancellation before dispatch and Editor shutdown. They cannot preempt a synchronous importer occupying the game thread.

A local query is not a wait for an outstanding download. Newly downloading or repairing content without a completion record is absent from `downloads`; `files` returns `fab_download_not_ready`. To consume that content, finish or recover its original download Operation first. An existing published record remains readable during read-only verification; import still performs fresh verification.

## Identity, completeness and output

Search defaults to `library`. Free search uses Fab's free catalog filter and does not imply ownership or acceptance of a license. Search returns a native page, not a complete inventory count. The category tree represents global native taxonomy, so it does not reuse unrelated library counts.

`categories` and `search/asset(scope="free")` do not invoke native authentication or `/p/authenticate`. They still use the enabled Fab plugin, background native browser and existing same-origin request owner. Fab can require an interactive access check or return 401; those responses retain their normal explicit diagnostics. A successful public query does not prove My Library access or download entitlement; use `status` for that distinction. Default library queries and every download retain authentication and session-cache invalidation.

Pages are positive integers; zero, negative and fractional inputs are rejected rather than normalized. Search traversal rejects malformed or repeated cursors instead of treating them as the end of a complete result. Malformed native category or format structure is a protocol error, not empty availability.

The native library row identity differs from the listing identity. Adapter internals retain the correct endpoint identity and deduplicate by listing identity; public callers carry the readable title and the shared name-selection fields. Default detail/download resolution checks all native pages for the same title query before selecting. Ambiguity is reported with semantic choices, never a random first match. For `fab.asset(scope="free")`, copy the search result's public `listing_url` to resolve that exact listing without traversing broad title-search results. The returned title and supplied semantic selector are still checked; this URL never substitutes for a private library row identity or download authorization.

`styles` is an array of native free-catalog Style facet slugs copied from Fab's public search URL. The visible Rendering Style and Period/Theme groups share repeated `styles` parameters (for example `stylized` and `medieval`). Combine these facets with type/category and optional text `query`; text search alone is not a native style filter. No locally invented list is treated as Fab's complete taxonomy. Library Style support is unverified and is explicitly rejected instead of silently dropping that filter. Keep all filters unchanged while paging.

Details expose only needed public metadata. Missing engine/platform metadata is unknown, not evidence of compatibility. Descriptions are plain text capped at 600 characters with a truncation flag; full terms remain on the public listing page. Import returns at most 20 asset paths with actual total counts and an explicit truncation flag. Cache listing is paginated.

Local download pages retain sorted cache-directory order and skip invalid completion records. Listing reads only through the requested page plus one valid record needed to establish `has_more`; a page beyond the directory-count upper bound reads no receipts. This does not introduce a persistent cache or change fresh verification before import. `fab.files` still examines the complete inventory to return its matching `total` and validate archive entries.

## Download and import

Download defaults to a unique standalone GLB when available, then a native UE format or the sole format; multiple files require an explicit real filename. Same-name files use the detail result's semantic `file_select`, backed by the same common name-selection mechanism. A supplied file selection is never replaced by that default. `save_as` controls a readable project-local name and cannot silently rebind another source. Completed records contain provenance and file integrity information, never authorization URLs. Retry obtains fresh authorization and verifies/reuses or repairs the same source cache.

A binary completion record must bind its selected filename to its single verified inventory entry. Corrupt records (`fab_cache_record_invalid`) and changed payloads (`fab_cache_file_changed`) are not importable; retry the same completed download selection to repair them. `fab_download_not_ready` means there is no completed record: recover an outstanding download, or select a completed entry from `fab.downloads`. File sizes must be nonnegative integers, and inventory paths must be safe and unique. ZIP inventory and extraction validate every original entry before any name-based deduplication, including case collisions and Windows filename aliases. Each extraction clears the previous private extraction so obsolete dependencies cannot participate.

Native UE content packs preserve canonical `/Game` package paths; `destination` is omitted or `/Game`. Omit `entry`: these packs import together to preserve references; a supplied entry is rejected explicitly. Use `fab.files` to inspect their contents. Existing packages are not overwritten. Native summaries, supported version/flags and end tags are checked without creating UObjects before publication. `fab_pack_header_invalid` identifies damaged source packages; `fab_pack_version_incompatible` identifies incompatible package or engine/custom versions. Headers and declared package sidecars participate in the shared AssetDurable inventory, backup, journal and recovery, and copied bytes are compared with the verified cache before reload. Plugin/project installers and unsupported loose native-pack files return a concrete diagnostic rather than being silently omitted.

Generic files use automated AssetTools with its current native importer and default translator. They create a new empty `/Game` folder, default `/Game/Fab/<title>`, without replacement. ZIP extraction validates every entry path and stays in private cache; `entry` selects an ambiguous primary file. Use `fab.files(download, query, page)` to inspect all choices; a bounded error preview is not the complete inventory. Dependencies remain adjacent. Imported packages are persisted through the common durability mechanism and reloaded before success. The original cache remains available as source data. Structured Interchange errors prevent publication even if some objects were produced; warnings remain typed diagnostics on successful results. Native APIs without structured results attach scoped feedback on failure. Private cache paths remain internal; public reasons identify the readable download or project asset.

Rollback is successful only when the shared durability receipt confirms `rolled_back`; successfully recording a `state_unknown` receipt does not mean restoration. An unconfirmed rollback returns `state="recovery_required"`, the original import error, recovery diagnostics and public durable custody. Inspect the returned SDK `Result.durable_journals` handles and reconcile the same transaction before deciding whether import may be retried. Do not replace recovery with a new import.

## State guidance

`fab.open` returning `opened` does not wait for asynchronous native persistent-session restoration. An empty native getter now returns `fab_native_session_unavailable` at `fab.native_session`; it is not evidence that the user signed out. If My Library already works, preserve that sign-in and diagnose the native-session mismatch instead of repeatedly requesting login.

Remote errors retain their safe `fab.session`, `fab.csrf`, `fab.authenticate` or `fab.request` stage and numeric `session.http_status`. HTTP 401 retains `fab_login_required` for existing consumers, but means that the background request was rejected, not that the Fab tab is visibly signed out. `fab_interaction_required` distinguishes an observed challenge page from an ordinary HTTP 403. The UAI background browser and native Fab tab are separate contexts; completing an interaction in the tab is not a proven remedy for a background-browser challenge. No token, cookie, response body or private identity is included in this diagnostic.

Download access denied: verify ownership and license requirements on the asset page; acquisition and legal acceptance require the user's action. A protocol-shape failure remains `fab_response_changed`; no token extraction or alternate unverified endpoint fallback is performed. Only `fab.status` reports overall Fab availability; a command-specific failure does not imply that the plugin or user login is unavailable.

Query commands require `uai:query`; opening the native tab, downloading and importing require `uai:operate`. Online commands require a supported enabled Fab plugin and native browser; local downloads/files/import do not require Fab authentication.
