# Public Authoring Consistency

本页定义结构化 HJSON authoring 在当前公开架构中的一致性检查。它只检查仍由正式
owner 维护的链路，不恢复旧 `uai_core` checker、命令 pack、任务级 audit 或旧 release
入口。

## Authority Chain

公开能力沿以下单向链路成立：

1. C++ 冻结 command registry 定义公开 command identity 与参数合同；
2. `UeAgentInterface.ExportCommandManifest` 把当前 registry 显式导出到 `Resources/UaiCommandManifest.json`，`tools/uai_binding/generate_bindings.py` 再从该投影生成 Python binding；
3. named method、`Client.execute()` 与 CLI 共用同一个 Client、Protocol 和 Transport；
4. command 经正式 ingress 进入 CommandService，再进入唯一 C++ 业务 owner；
5. 写操作由对应 owner 完成 compile/settle、持久化和独立 readback。

HJSON 的 schema、workspace、selector、operation 和 readback 语义由服务端 authoring
owner 持有。Python/CLI、skill 文档和测试不得复制这些业务决定。

目录 workspace 的机器基线由公共 composition 与 SemanticWorkspaceResolver 共同维护。
`unit_inventory` 行保留原 inline `envelope` 读取，也可通过互斥的 `envelope_ref` 指向
`.uai/baselines/` 中的 HJSON；文件根以稳定 unit identity 为 key，值为完整 captured envelope。
目录 manifest 的 inventory 可保持 inline `unit_inventory`，或通过互斥的
`unit_inventory_files` 引用 `.uai/inventory/` 下的文件；每个文件仍包含同一 `unit_inventory`
行数组。公共 resolver 合并后统一校验完整身份、引用与基线，跨分片重复同样拒绝。
embedded workspace 保留自包含的 inline 形式，不从外部解析 inventory 文件。
导出按已有物理文档归属稳定分片；多个文档可共用机器文件，使局部属性变化只使对应分片
失效，并控制文件数量。公开可编辑文件不变。
首次、用户明确full/ordinary消费各自完整输入；局部`/4` committed以同代目的publication和累计actual驱动，不先恢复完整值数组或完整Model。缺可丢last-layout不改变选择算法；真正所需行/span/名称由同代publication直接交，缺必需handoff明确停，不恢复完整目录/Model或全当前UE。下文完整compiler/layout的共享策略仅服务原本明确的完整输入，不授予局部缺资料时选择它的权限。
变化unit核实际声明、category/provenance、logical/physical/public-ref、类型与定义依赖；未变单位的已接受事实由原owner交接，不再逐值重判。inventory仍保留实际edit hash、pointer及外部content路径。
layout只把真实放置输入当依赖：普通PropertySet payload与不参与图命名的原生字段改变不重新分配名称；TG pin求值`value`由原graph projection owner明确归内容，id/name/direction/cpp_type及结构仍按原规则。定义内容和原命名owner读取的字段变化仍重规划真实影响范围。typed比较共用原精确语义，row SHA只证明对应真实序列化内容，不能替代当前native观察或作者字节保护。
其他单元新增、删除或移动不关闭无关行的复用；旧/新受影响bucket均失效，完整清单仍只含当前成员。

冲突、新增或未知情况重新分配，完整当前public-ref映射仍核验。packed property文档还要求成员集合、
每成员证明以及本文件实际依赖的递归property-definition schema/alias投影不变；
未知非definition依赖保持重建。独立普通unit及Actor/Component item-state文档在完整layout/ref映射和实际unit内容相等时复用文件；
集合keyed/hierarchy及graph仍从当前模型生成。packed definition的element
template可读取文档外模型，继续要求原有完整layout等价且无其他单元变化，不能只凭文件内成员未变复用。

实际node身份、完整pointer、field name、level、稳定投影/key-order及非inline上下文须一致。
片段仅弱引用 canonical node，当前调用的节点仍存活且 Pin 后身份相同才可复用；缓存不延长旧对象图寿命。
缓存受文档数、片段数和文本总量限制，复用仍重放原资源计量；可变JSON、动态投影或证明不足走原路径。
解析节点共享同文档不可变 source-unit
字符串，各节点独立持有其生命周期；原有构造入口、source/path/行列诊断及数字精度保持不变。
身份、captured envelope、类型和引用由原resolver/公共codec负责；真实legacy完整输入保留其compiler，普通局部Source交声明及变化意图，不先编译完整Model。生成材料的交接必须对应同代真实bytes与机器材料，不能把任意export model当作已解析输入。发布读回保持实际字节与已校验计划逐字节相等。
当前开发树局部Source使用原`UeAgentWorkspaceChangeObserver`的NTFS ExW连续会话先选文件，禁止owner全文件逐Observe/hash发现。明确full/initialize建立观察起点；StopServer/Shutdown关闭，SDK连接关闭不关闭。缺起点/通知loss/根身份失效具体报错，不用W/USN/轮询/全目录reader替代。目录结构事件缺子树绑定时报该接缝，不递归发现全部正文。通知候选不是写完/内容相等证明；实际读取和发表仍保护真实R/W字节。用法及平台边界见[workspace-file-changes.md](../workspace-file-changes.md)。
`pending_author_documents`由同次actual及作者三方写回产生，必须与publication generation配对；缺字段/未知不能猜空或自动bootstrap旧Source。Selected是OS候选与尚未消费作者文档的并集。OS ack、SourceCheckpoint、每目的through各自独立；读取未应用A后只看到B事件仍须处理A+B。系统发表的真实bytes/hash仅用于识别已知系统事件，不能证明被保留作者B已应用；cut之后事件合入原pending集合，消费B后的成功发表才移除。未知旧state在原接缝报错，需调用者明确选择受支持的完整输入，不能局部失败自动升级。
原publisher直接交同代实际plan的原bytes/ComparisonHash与机器fragment spans，不构造每个公开文件的AST。上次AST可丢；已有公开doc缺树时仅从确切旧publication raw初建该旧版本，再调用Myers/原Update。缺raw或Update失败明确停，不Build当前新doc重试、向父扩大或换parser。显式初次/完整输入的原parser不属于这条失败分支。共享raw/span/AST仍归原512MiB owner，不强保整代Model，不增加预算。
managed行先核同表示edit-node digest、声明及真实ref依赖；精确命中在captured-value AST前结束。真正content_ref走原Expand，非精确行由原typed等价/只读/presence判断。原inventory给稳定ID/ordinal和真实span，声明reader同步消费原parser片段只提类型/owner/ref；成功不恢复绝对行列、不留AST，真实错误才恢复绝对来源。声明条目持同目录append-only物理RowIndex，后续FindRow验证UnitId后直取，不重新逐行定位；不能借该索引跨generation推语义身份。真实值/名字按需恢复来源，scope结束释放；缺raw不为诊断整inventory重读，缺captured_values不切whole-unit decoder。
resolver的跨调用候选只来自上一成功解析：实际inventory行、公开行、baseline envelope的精确内容分别证明，
整文档或机器分片变化不自动使其中全部语义行失效。引用解释记录实际lookup的key、命中值及miss；
全引用表改变时只复核该行真正读取过的绑定，证明不完整则扩大重验。当前source-unit/pointer/行列从真实新解析节点重绑，
原算法已选安全节点后，未知来源/边界/fragment失败直接原错误，不换整文件算法；资源照原owner计量，最近raw不代替已消费作者基线。原512MiB语法owner保本版本配对，不另复制整批authored-row根。可丢lookup证明缺失只重验这条真实绑定，不能扩大到完整Source；服务退出清空，跨会话不承诺命中。
inventory解析后的只读字段由分片与当前读取共享。envelope_ref行保留原source span/provenance和单份分片UTF8，成功路径直接消费紧凑字段，错误定位才按原span物化；inline envelope保留原AST。source/baseline绑定及路径覆盖仍属于本次读取。
当前实际分片内容证明同一身份集合时复用成功的全局identity/ref-map结果；分片变化仍逐行核对身份字段，
二次读取变化则恢复普通全局重复身份校验。该证明不要求manifest generation或全引用表hash不变。
成功typed row的当前source document和完整provenance相同、实际lookup依赖及预算均满足时共享只读proof；
来源或依赖变化仍重绑/重验，syntax proof不能代替成功语义proof。
同request的已接受source还可向共同publisher交接纯syntax成功及完整parse charges：SourceUnit大小写精确、解析文本UTF8 hash等于当前计划bytes hash。普通文档核同一成功resolution的Parsed；已主动退休AST的inventory则核本次成功hash和完整parser计量，仅保留scope内路径/hash/charges，不重新持有AST。计量不完整或仅有聚合baseline费用时不借作纯syntax。v2/v3均在各自实际write/readback或完整guard字节证明之后消费，不传AST/model，不替代source checkpoint、最终路径/lease或原子发布；无完整证明回原parser。stage的files是逻辑遍历，v3只有Changed集合真正写读。
原parser入口还可从 `Saved/UeAgentInterface/HjsonSyntax/v1` 恢复成功纯syntax派生材料；key绑定当前实际Text、大小写精确SourceUnit、parser/字符表示/压缩器版本。AST保留原数值lexeme、文本/键、对象与数组顺序及全部provenance，原解析charges向本次资源owner重放；语义行、lookup、baseline/compiler和当前FileID/bytes接受检查不由它代替。单blob展开32MiB、压缩磁盘总预算512MiB，只有当前一次恢复的AST交给原parser消费者，不另常驻多代AST。缺失、损坏、旧版、超限回原解析；写入在非阻塞跨进程mutex下真实重计目录、逐出并原子替换，竞争/失败仅放弃可丢弃缓存。首次生成费用仍计入当前调用；不将UObject、文件lease或成功语义token持久化。任何parser语义/provenance/成功诊断或计量变化必须更新私有版本。
已共享的成功row通过本次workspace的只读binding view提供source、baseline及source document；
Import/Rebase的单项查询直接消费该view，变化或重绑行优先使用本次稀疏覆盖，避免为未变行再装配三份完整映射。
原完整映射getter与编译错误定位仍可按需物化；资源计量、真正完整compiler消费者及最终namespace fence各保其职责，普通局部意图不先物化完整值数组。
view共享当前有界proof及其必要来源背板，不额外保留旧model或UObject，自身不替代实际文件变化发现。
对完整成功的inventory分片，resolver还保存原序typed行组及其Units、来源绑定、edited/keyed-root输出和资源charges。
当前真实inventory membership、公开文档字节与解析对象身份、baseline内容以及实际lookup结果证明仍有效时，
source和下游直接消费该组，不再次逐行规范化路径、找节点或重插来源索引；变化组沿原逐行路径处理。
分片顺序/成员/路径改变、content-ref展开、来源身份失效或证明不完整均回退，manifest generation和全引用表hash变化不单独令全部组失效。
目录和祖先reparse检查、起止namespace fence、真实完整compiler消费者及其原SHA保持；资源聚合失败原子回退逐行计量和诊断，不改变业务scope。
组仅弱记完整文档身份，借用节点须由本次实际读取强持并核对后使用；不强持另一份完整AST或model。
索引、反向依赖、组数组及自有字符串合计最多64MiB，只接纳当前成功候选；typed行按512MiB真实持有成本及完整inventory分片准入，inventory syntax另按512MiB背板预算，lookup预算继续约束内容。
纯public syntax候选另按512MiB实际AST节点、源名字和容器allocation计费，不以源码字符数近似整棵树；优先准入现有inventory组的完整document依赖闭包，再准入可容纳的剩余文档。当前完整读取不受可选缓存预算截断。相同当前bytes和大小写精确的SourceUnit复用同一Parsed对象，当前FileID/lease仍独立验证；不同来源位置不因内容相同合并。inventory的canonical小写sha256文本内部可存32字节，非canonical旧文本保留原样，外部hash字符串/诊断和原TCHAR指纹材料不变。
局部预算不足只退出对应文件/行/组的额外证明，不能因展开条目超过200000清空全部已有效内容。typed row来源是逐unit浅包装，其准入按当前已验证SourceUnit对应的实际文件背板，不能将包装地址与whole-file parser地址比较；content_files/content_ref等跨文件展开没有完整证明时沿原路径。完整当前输入、来源诊断和资源计量不被缓存预算截断。
不同lookup证明对象的key和实际命中值或miss严格相同可共同接纳，但每个保留对象身份都计入原16MiB背板预算，引用边仍限2M。typed总预算按本代实际lookup对象、共享source名字、unit声明字符串、不可变容器和canonical节点身份一次计费，行私有存储仍完整计量；拒收组同时撤销该组新增的共享身份计费，不丢当前来源或基线。当前已接受workspace强持本次source backing，跨调用row proof仅持浅层形状、provenance和弱child；借用失效则重新解析。成功资源delta按完整维度和值共享，replay仍进入原资源owner；没有keyed根的行不保存空集合。
同一inventory解析scope内，已规范化且大小写精确相同的EnvelopeRef共享不可变路径，syntax与成功row共持；临时路径查找表随parse退出。inventory和typed两个预算各自对仍持有的唯一路径backing完整计费，不能依赖另一个cache存在而免除本owner费用。lookup pool的临时map-key和proof自身Key在调用期分别计量；成功row/group只保留proof的Key/Result及控制块，长期预算不再重复收取已经释放的pool map-key/节点。
公共semantic unit在原验证/NormalizeSet之后共享精确相同的少量不可变容器，source/category/target仍独立。canonical factory仅在完整grammar与逻辑资源计量之后共享精确kind、text/number lexeme、成员键与子身份；数组顺序保持，对象按原canonical排序。弱索引固定有界，碰撞、容量或形状不符走原构造，不以数值近似或row hash合并source/native模型。Stop/reset清理索引；预算只限制额外证明，不削减完整输出。
SourceLoader以同一root观察会话和实际读取集合R完成本请求接受；局部路径不再重建/复核完整目录快照来寻找变化。root containment/reparse、实际绑定/机器版本保护仍在原owner；发表写集W和实际读R独立于owner的全部成员。原同文件proof可复用，丢失则正常读所需文件真实bytes，不切完整Source。后续真正读取的类型/行/guide纳入同一R，而不是重新打开全部accepted文件。
同请求Source接受与后续发布checkpoint分别在真实时点核R/当前字节；late checkpoint不代替native前校验。新路径候选由OS，机器namespace由同代owner，内容proof不承担事件连续性。显式完整输入、独立legacy完整loader仍按其明确合同读取；不能因local上下文unset走该分支。header/generation/captured作者基线、当前native before、已接受desired和after各自独立，普通局部不先形成三份完整模型。

`workspace_format` 可选`v2|v3|v4`，新目录默认`/4`；显式v2/v3导出仍是完整格式生成职责，但本开发树局部目录导入/committed只接资料齐全的`/4`。不承诺旧目录可自动升级或继续局部编辑，缺项必须先由正式producer接通，不能换目录掩盖原请求。`/4`普通链不生成旧整模型flat SHA、完整layout或第二inventory来补资格。旧writer不能续写新store，切换沿正常Editor生命周期。`/2`原目录事务及`/3`、`/4`真实write set保护保留；完整namespace与最终并发字节/rename保护仍由原publisher负责。
`/2` 在暂存内容完整读回/验证后执行target version及最终source checkpoint；checkpoint重新绑定当前逻辑文件并验证FileID/有效lease或实际bytes hash。成功后才退休该目录的可选RH读取缓存，随后旧目录移入backup、新目录原子替换，并按完整paths/hash/owner核验最终目录；失败仍走原journal/rollback。退休先令proof失效，IOCP完成前保留其异步存储，后续读取不能再使用该lease。RH缓存本来不提供checkpoint至swap的持续写排他；此旧目录发布路径不能宣传为`/3`提交点完整W∪R guard合同，也不以IOCP存储仍存活声称内容证明仍有效。
`/2` 私有stage最多两路独立write/readback、64文件/8MiB批次；主线程按原文件顺序消费错误、parse与计量，退出前等待全部worker，不共享可写inode。final路径实际读前取得的新RH proof只在读后当前identity/pending及原文本hash规则成立时交给resolver的内容观察owner；不移交stage/旧目录proof、不授予语法或语义证明，final失败先退休新proof再走原恢复。观察表达到16384项时保留已有有效项，新路径不能准入仍实际读取，不整表清空。
公共文件proof弱索引达到容量时只清理expired或原生lease已结束的条目，保留仍pending的索引，避免仍由当前source持有的proof失去查找入口后被publisher重复申请。若仍满，仅新路径不进入可选弱索引，实际读取与原16384操作/4MiB路径预算不变；pending只用于可选索引退休判断，不代替当前逻辑路径、FileID、type和bytes检查。同scope强guard可向当前文件观察交接已绑定句柄；观察者立即查询当前attributes/type/stat，移除的是callback内的重复ordinary查询。其它直接消费file proof的入口仍各自核ordinary、identity和lease有效性，不能因持有guard而缓存文件类型至其生命周期结束。
公共staging在成功实际readback后封存raw hash/byte count对应的decoded hash/character count，编码事实最多16384项/8MiB，不保存bytes/AST，也不是当前文件或语义证明。`/2`最终实际读回/hash与新lease成立时消费该事实；`/3`在committed后、强guard仍持有时，仅为本次changed/new HJSON核最终逻辑路径、实际bytes/hash及新lease后交同一resolver来源观察owner，未变文件不增加整目录读回。可选交接不成立只不准入缓存，不改变已提交成功或恢复语义；stage proof不跨rename冒充final proof。
旧 reader 从永久 schema 入口拒绝 `/3`；新正式 reader 在读取前后要求同一 committed generation，
busy/变化时拒绝候选，不重放原生 apply。此保证不扩展到裸文件工具的任意跨文件快照读取。

`/3` 的 prepared/staged/publishing/committed/cleanup journal 由公共 publisher 持有；
最终 committed manifest 发布前中断恢复旧代，之后只清理本次备份。未知第三方内容保留并返回恢复冲突。
export 可执行恢复；原生已应用而 refresh 失败时，应先按回执恢复并重新观察当前原生状态，不能直接重试 import。
当前受影响文件提交要求 Windows backend 实际授予 RH lease，并取得短期文件写/删除排他 guard；
不支持的平台/文件系统、持久 writer、guard 预算不足或不支持的 staged verifier 明确诊断，不能静默绕过保护。
有旧reader或不同backend需求时可显式生成v2输出；这不恢复本开发树旧目录局部导入/committed的自动兼容路线。
GenerationFiles的目录能力只在本次发布/恢复scope存在：以GENERIC_READ、share READ|WRITE且不share DELETE固定实际目录身份；逐层相对句柄打开并拒绝reparse。只有完整祖先链已由同一scope保留时才能直接复用精确父目录能力；预算/句柄复制失败时不保留断链子能力。Windows仍允许WRITE_ATTRIBUTES改变空目录，因此创建/rename另用相对OBJ_DONT_REPARSE及短期delete-on-close普通文件pin，保持目标目录在写入窗口非空。journal、staging、commit、rollback和private cleanup共用这一owner；拒绝时不沿绝对路径重试，不覆盖第三方内容。目录能力最多16384条及4Mi路径字符，scope结束释放，private cleanup只释放正在删除的子树。当前backend要求本地盘符路径，不支持时明确诊断；此能力没有替代source的完整namespace扫描或长期内容proof。
source 的长期 RH proof 只在内核仍 pending、当前 namespace/FileID 相同且没有 reparse 时复用；
proof 丢失/重启/预算不足回实际读取，不能把 mtime 或通知当成功解析证明。单 worker、16384 proof 和路径字符预算有界，停止时清理。v3提交当前完整读集的proof保留至最终fence；私有staging文件在真实lease排除既存可写映射并读回后，由同一持续strong guard禁止新writer/替换，其proof随单文件观察释放，不进入跨调用观察缓存。这样结构批次不会仅因同时缓存old+new两份文件证明耗尽后端；真实预算不足单独报告guard_budget，实际guard读失败保留原诊断，不伪报mmap/文件系统问题。
SourceLoader的Before与After都可使用同次相对路径metadata能力，仍真实枚举全部名字、核当前根/逻辑绑定和ordinary/type/FileID/stat；Before不签发内容或语义证明，After对实际消费文件保留当前bytes接受fence。只读目录share-delete，不新增deny-delete，也不以目录lease跳过新名字发现。publisher在自己的强guard已覆盖当前路径时可把该handle交给file-proof作identity/pending核验，减少同路径重开；关闭/改名/未受保护路径回原路径核验，完整稳定读集、mmap拒绝和checkpoint/finalfence仍保留。
compiler 自身弱记一个成功候选；精确结构一致才共享已验证索引/引用与 owner-cycle 证明，
变化或失效回完整检查。当前值合法性、原资源计量与完整外部 fingerprint 字节流保持。
原UnitMaterial按最多256个有序unit保留UTF8字节与每unit字节边界。整块当前immutable storage精确相同时直接消费整块；部分弱身份失效时，仅消费当前精确相同unit的原字节区间，其余仍按原grammar生成，不能把一个失效邻居扩大成整个材料块失效。逻辑首unit/位置仅筛候选，真正的复用条件仍是各unit弱storage身份；所有弱身份失效的块退出，失败编译不接纳新块。当前header与全部字节仍按原顺序进入原线性SHA，资源计量按完整当前unit/value数和字节数执行。memo最多8192块/64MiB，包含buffer、字节边界、逻辑候选索引、容器及弱控制块估算，超预算局部不准入，不强持unit/model/UObject，Stop/Shutdown清理；source/native分别证明，不省掉完整结构/引用校验。
miss材料仅在canonical object键序按原FString IgnoreCase比较器严格递增时直接消费；折叠同值/反序仍执行原排序，不把canonical的CaseSensitive排序当作同一外部SHA顺序；单value unit免临时keys数组，多value仍排序。输出token和原SHA顺序不变。layout同一immutable unit可省逐字段重复比较，但definition读取的model级名称/首选alias/public-ref仍逐项核对。
未命中时同一材料grammar直接向有界UTF8 buffer追加，不先构造整块FString再转换；字符串token保留原UTF8字节长度、数值lexeme、header/BaseRevision和原线性SHA顺序。source/native不同storage仍分别证明，不把row HJSON hash当作不同编码的compiler材料hash。没有证据支持按构建cost/Uses淘汰可改善跨流命中，该候选策略退出，固定64MiB预算不足仍正常重建。

`scripts/ue/UpdateUaiCommandSurface.ps1` 是显式刷新命令 manifest 与 Python binding
的开发动作：从当前 registry 导出 manifest，再由 generator 重建 binding。真实可用性由
当前改动直接相关的 public input、UE 状态和独立 readback 证据判断。

`editor.session` 与 `capture.image.execute` 的策略参数、subject、用法和结果说明由对应
C++ policy descriptor 持有，注册时完整投影到 variants；固定 `editor.safe_exit` 由自己的命令
拥有合同。修改 descriptor 后须使用新构建刷新命令面，不能只修改生成 binding 或静默隐藏缺失合同。
图像策略的副作用按所选策略说明判断，例如 PCG viewport 的 Actor framing 会保留相机变换。

## Command And Candidate Discovery

- 已知 command 且签名已明确时，直接使用生成的 named method。
- 不知道 command 时，先调用 `query.command.search` 取得名称，再用
  `query.command.usage` 批量取得 named 最小调用；复杂 schema、variant 或失败语义以生成 SDK、正式 schema 与领域文档为准。
- 动态调用使用 `Client.execute(command, params)`；机器版本校验由 SDK 和 wire 内部完成。
- factory、node、component、actor 或其他 candidate 查询返回的 identity 必须可原样
  进入对应 create/apply 输入；调用侧不得建立别名表或领域映射。
- HJSON 文件导航只依据正式 export profile、`included_files`、`read_order`、manifest、
  index 和 ref，不扫描 sibling 或历史文档猜测字段。

## Failure Handling

1. 先确认失败属于 manifest/binding、Client/Protocol/Transport、CommandService、领域
   owner、持久化/readback、正式文档或 Pak/installed 同步中的哪一层。
2. 在该层的唯一 owner 修复，不在 SDK、CLI、skill 或单条 route 内增加业务兜底。
3. command 返回成功但 UE 状态或独立 readback 不符合语义时，停止依赖该成功结果，
   保存输入、Result、readback 和运行日志，并修复服务端 owner。
4. 只在当前完成结论需要时取得直接覆盖受影响行为的证据；不把测试、全消费者复跑或
   Pak/installed 同步设为继续开发的前置。

## Current Boundaries

- 正式能力全集与参数只由当前 manifest 定义，不在本文硬编码命令数、profile 数或
  domain 数。
- `query.command.search/usage` 与按生成 SDK、正式 schema 与领域文档 只解决公开 command 发现；领域 candidate discovery
  仍由对应 C++ owner 返回可直接消费的 identity。
- 真实可用性只由当前正式入口的实际结果与所需 readback 支撑；生成、同步、测试或
  文档本身都不签发领域完成。
