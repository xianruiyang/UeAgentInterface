# Generated authoring examples

普通 `llm_authoring` workspace 在根 `examples/` 中导出只读说明。它用于回答“这个空列表里如何填写第一个值”和“这个集合如何新增成员”，不需要另一个查询命令，也不改变 export/edit/import 操作。

## 阅读与使用

- `examples/index.hjson`：业务文件到说明文件的导航；只定位本次需要编辑的文件。
- `examples/files/<业务文件路径>`：`edit_file` 是真实编辑文件；`at` 的 JSON Pointer 指向其中的值，冒号后的名称区分同一位置的示例。
- `examples/types/`：由类型与约束生成的共享值示例。相同规则复用，名称用现有公共消歧机制分配。

将所需 `example` 合入 `edit_file` 的指定位置；保留既有集合成员和身份。所有 `<...>` 都是待填写说明，要替换为当前目标的候选、引用或参数。示例只说明最小形状，不代表期望效果、业务默认值、必填字段全集或可复制的旧实例。

创建节点、组件、模块或 owned object 时，选择器的位置由各自当前创建合同决定。示例不代选候选；查询结果中的 `name/select`、适用的 `candidate_context` 及必要关系仍来自本次上下文。已有结构继续使用导出的定义、类别、引用和接口。

## 公共生成与扩展

1. 基础值、结构、数组、集合、映射、可选值和引用递归消费现有类型描述。结构示例仅展开少量可编辑成员；省略字段的语义由原导入链和原生默认值决定。
2. 专用公共值复用其现有 codec 的形状或正式模板；集合规则消费本次真正采用的 keyed contract，包含原生子集合和新增默认值来源。
3. 需要关系或生命周期语义的逻辑记录由所属规则补充，例如 AnimSequence 与 Montage 共用 Notify 示例。规则只提供说明数据，文件组织、序列化、消歧和导航共用公共发布器。

生成不依赖列表是否已有实例，不复制实例 GUID、捕获 identity 或已有对象内容来猜新对象格式。需要目标上下文的字段保留明确占位和说明；不把未知字段伪装成可直接执行的值。

## 与导入隔离

说明在语义模型及身份已生成之后投影，不加入 `unit_inventory`，不作为 `content_ref/interface_ref` 编辑载体，不参与业务差量和基线比较。缺失、修改或删除说明文件不会更改资产；正常刷新会重新生成当前说明。不要把 `examples/` 文件作为业务分片引用。

示例不是另一份可写 schema，也不新增导入门禁。原有字段诊断、未改内容保留、默认值、原生更新、保存和刷新仍由原公共链路承担。
